--------------------------------------------------------------------------------
 3. OBFUSCATION (bin2bin)
--------------------------------------------------------------------------------
  * Control-flow flattening + junk bytes: linear disassembly desyncs; basic blocks
    reached via a junk dispatcher with always-taken jo/jno (and jl/jge) pairs.
  * String encryption: strings are built at runtime - the code movdqa-loads
    scrambled 16-byte chunks from .rdata onto the stack, appends immediate bytes,
    then calls an in-place decoder. Transform = XOR-by-index (buf[i] ^= i) over the
    assembled buffer. Chunks are permuted in .rdata, so naive contiguous decode
    only works for some strings.

Faster than fully reversing the string builder: let the binary decode its own
strings and read them from memory.


--------------------------------------------------------------------------------
 4. STEPPING INTO THE MACHINE - ctypes debugger
--------------------------------------------------------------------------------
A small pure-Python (ctypes) Win32 debugger:
  1. CreateProcessW(..., DEBUG_ONLY_THIS_PROCESS), stdin/stdout via pipes
     (feed "\r\n" for getchar; capture output incl. spawned children).
  2. WaitForDebugEvent / ContinueDebugEvent loop.
  3. Hook time APIs: write 0xCC at the export entry, and on hit EMULATE the whole
     function (write value to *RCX, RIP=[RSP], RSP+=8).
  4. At a breakpoint, walk memory via VirtualQueryEx + ReadProcessMemory and regex
     printable strings.

4a. Which time API?
    Hooking kernel32!GetSystemTimeAsFileTime/Precise -> 0 hits (modern Win10/11
    std::chrono reaches the clock via ntdll!NtQuerySystemTime / KUSER_SHARED_DATA).
    Hooking NtQuerySystemTime -> 3 hits.
    NOTE: injecting any timestamp via NtQuerySystemTime did NOT change the gate
    (it reads time via a path that bypasses the hook). Doesn't matter - we solve
    offline.

4b. Memory dump -> ciphertext
    Committed-memory dump revealed already-decoded constants, including:
      - 2147483647  (the 2038 timestamp - flavor)
      - AES ciphertext hex:
        4c4635258cf6eca5d80b8e050a9e5b04
        f1a9c979bc55f3f4773971ed2f81a969
        67bb3569fa002f549cc970a18779b3a7   (48 bytes)


--------------------------------------------------------------------------------
 5. BREAKING THE CRYPTO (offline)
--------------------------------------------------------------------------------
AES-CBC-128. key = b"nicetryboogeyman" (16 bytes). ct = 48 bytes above.

5a. Blocks >= 1 need only the KEY.
    P_i = AES_dec(C_i) XOR C_{i-1}  for i >= 1.
    Decrypt with zero IV -> block0 garbage, but bytes 16-47 correct:
       b't0_l34rn_fr0M_n0T_t0_l1V3_1n}\x03\x03\x03'   (valid PKCS#7 pad of 3)
    => key + ciphertext alignment confirmed; second half of the flag obtained.

5b. Block 0 needs the IV; known plaintext fixes the prefix.
    dec0 = AES_dec(C_0)   (single-block ECB decrypt)
    IV[i] = dec0[i] XOR P0[i] ; P0[0:4] = "CMO{"  => IV[0:4] = "0000"
    => IV is a zero-padded decimal string (matches "amalgamated UNIX timestamps").

5c. The IV value.
    Real amalgam = 537068053  => IV = b"0000000537068053".
    AES-CBC decrypt with this IV:
       CMO{5h3_p4St_1s_t0_l34rn_fr0M_n0T_t0_l1V3_1n}

    Intended "educated brute force": the gate restricts to the Feb-2026 window and
    the IV derives from a timestamp; a player either runs it in-window (program
    builds the real IV) or brute-forces the timestamp/format offline against the
    known plaintext "CMO{".

5d. HONEST NOTE ON UNIQUENESS (!!):
    "IV = 16 ASCII digits" narrows but does NOT uniquely fix block 0. Where two
    readable leet chars are both reachable via XOR with a digit, the choice is
    ambiguous (~8.7e10 wordchar block-0 readings satisfy the constraint).
    Example: CMO{5h3_p4St_1s_...} (IV 537068053)  and
             CMO{7h3_p4St_1s_...} (IV 200537068053)
    BOTH yield valid all-digit IVs and both read as "the". Only the REAL IV value
    disambiguates. The official flag uses 5h3.

--------------------------------------------------------------------------------
 8. TAKEAWAYS
--------------------------------------------------------------------------------
  1. CBC leaks: blocks >= 1 need only the key - recover most of a flag pre-IV.
  2. Known plaintext (CMO{) yields IV bytes and reveals the IV format.
  3. Don't over-trust a charset constraint for uniqueness; it narrows, not solves.
  4. The flashy theme can be misdirection (2038 was flavor; gate = CTF window).
  5. A ~200-line ctypes debugger beats fighting a flattened/obfuscated binary
     statically - let it decode its own strings and read its memory.
  6. Keys hide in build artifacts - always check the PDB path.
